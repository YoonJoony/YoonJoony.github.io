# YUN.LOG 화면·동작·구현 기준

최종 검토: 2026-09-29

이 문서는 사용자가 확정한 메인과 Posts 시안을 실제 Astro 코드로 구현할 때 사용하는 기준이다. 이 문서를 기준으로 1차 구현을 완료했다. 구현 결과와 실행 방법은 README.md 및 docs/writing-posts.md에서 확인한다.

## 1. 기준과 적용 범위

### 확정된 시안

| 화면 | 기준 이미지 | 설명 |
|---|---|---|
| 메인 | [main.png](design/main.png) | 기존 `01-home-v4.png`. 사용자가 확정한 v3에서 헤더의 Projects를 Posts로 변경 |
| Posts | [posts.png](design/posts.png) | 기존 `02-posts-v1.png`. 폴더와 첫 글을 선택한 상태 |

**두 화면의 구성, 차콜 테마, 폴더와 글 카드의 들여쓰기 방식은 사용자 확정 사항이다.**

본문에서 `구현 기본안`이라고 표시한 내용은 아직 화면으로 확정하지 않은 세부 동작에 대한 제안이다. 이 구분을 유지하여 기술 선택을 사용자의 확정 요구로 오해하지 않는다. 시안의 날짜·태그·사진·소개 문구는 실제 게시 정보와 구분한다.

현재 구현 범위로 준비할 것은 공통 화면, 메인, Posts 탐색과 글 읽기, Markdown 메타데이터다. 뉴스 자동 수집·요약·발행 작업과 운영 일정은 후속 기능이다.

### 설계 시작 시 확인한 사항 (현재 구현 상태는 아래 참조)

- 실제 Git 저장소는 `yunBlog/yun-Blog`이다. `copy_folder`와 기존 `output/blog-design`은 그 바깥의 형제 경로에 있다.
- Astro `^7.3.5`, MDX, RSS, Sitemap을 사용하고 GitHub Pages 배포 설정이 있다.
- `src/content.config.ts`는 이미 하위 폴더의 MD·MDX를 읽는다.
- 현재 필수 글 정보는 `title`, `description`, `pubDate`다. `tags`, `draft`와 탐색 트리는 아직 구현되어 있지 않다.
- 현재 글 주소는 `/blog/<id>/`이고, 홈·목록·본문은 기본 템플릿 화면이다.
- `copy_folder`에는 Markdown 11개가 있다. 본문이 있는 파일 9개, 빈 파일 2개이며 모두 프런트매터가 없다.

### 1차 구현 반영 사항 — 2026-09-29

- 기존 Astro 프로젝트에서 메인·Posts·About·차콜/밝은 테마와 모바일 동작을 구현했다.
- 사용자가 이번 배포에 공개를 선택한 기존 학습 글 9개를 저장소 안으로 복사했다. `09-22.md`와 `입문시 참고글.md`는 초안으로 유지했다. `입문시 참고글.md`에는 이후 본문이 추가되었지만, 선택한 9개 외의 글이므로 자동 공개하지 않았다.
- `python_기본기.md`의 중복 slug를 `python-study-roadmap`으로 정리했다. 작성한 본문과 다른 메타데이터는 보존했다.
- 사진을 제공하기 전까지 생성한 임시 공통 대표 사진을 사용한다.
- 뉴스는 별도 Markdown 컬렉션에서 원문 링크를 받아 최신 3개를 표시한다. 현재는 실제 데이터가 없어 준비 중 상태다. 자동 수집·발행은 후속 범위다.
- 기존 기본 글 6개는 `legacy` 컬렉션으로 보관하고 `/blog/<id>/`를 `/posts/archive-<id>/`로 정적 리다이렉트한다. 새 목록·RSS·사이트맵에서 제외하며 이전 글 본문에는 noindex를 적용한다.
- 데스크톱은 목록과 본문이 각각 스크롤되고, 모바일에서는 선택한 글과 목록을 전환한다. 실제 글의 HTML은 각 주소에서 미리 생성한다.
- 아래의 초안 준비 기록은 구현 이전 상태다. 현재 공개 여부는 저장소 안 `src/content/blog`의 frontmatter가 기준이다.

## 2. 두 화면의 역할

| 화면 | 방문자가 하는 일 | 중심 내용 |
|---|---|---|
| 메인 | 작성자를 알아보고 최근 기록을 발견 | 소개, 최근 직접 작성한 글, News Research |
| Posts | 분야와 폴더를 탐색하고 글을 읽기 | 태그 필터, 펼침형 폴더와 글 카드, 선택한 글의 본문 |

메인의 최근 글과 Posts의 글은 같은 데이터다. 같은 Markdown을 두 번 작성하지 않는다. 메인 카드를 누르면 Posts의 해당 글로 이동하고, 왼쪽에서 그 글이 속한 폴더 경로도 펼쳐져 있어야 한다.

## 3. 공통 UI — 확정

- 헤더: `YUN.LOG` / `Blog` / `Posts` / `About` / 테마 전환.
- 로고와 Blog는 메인, Posts는 글 탐색 화면, About은 소개 화면으로 연결한다.
- 현재 페이지 메뉴에는 밑줄과 현재 위치 표시를 적용한다.
- 헤더 구분선과 본문의 양 끝은 **동일한 컨테이너**를 사용한다.
- 기본 테마는 중립적인 진한 차콜. 흰색 제목, 회색 본문, 얇은 회색 구분선, 절제된 태그를 사용한다.
- 글 카드의 대각선 화살표는 표시하지 않는다. 폴더의 펼침·접힘 표시는 사용할 수 있다.
- 푸터: 저작권 표기, GitHub, RSS.
- 헤더 명칭은 `Posts`로 통일한다. Projects와 Newsletter를 헤더에 추가하지 않는다.

### 구현 기본안: 크기와 접근성

- 전체 컨테이너 최대 폭은 약 1280px, 작은 화면의 좌우 여백은 20px부터 시작한다. 최종 수치는 시안과 비교해 조정한다.
- 기본 색: 배경 `#181818`, 보조 면 `#242424`, 제목 `#f5f5f5`, 본문 `#b5b5b5`, 선 `#3a3a3a`.
- 한국어를 지원하는 시스템 글꼴을 사용하고, 본문은 16~18px와 약 1.7의 줄 간격을 기준으로 한다.
- 버튼은 키보드로 조작할 수 있게 하고 포커스 테두리를 제공한다. 선택 상태를 색상만으로 구별하지 않는다.
- 문서 언어는 `ko`, 날짜 표시는 한국어·Asia/Seoul 기준으로 일관되게 처리한다.
- 테마 버튼은 차콜/밝은 테마를 전환하고 선택을 저장하는 안을 기본으로 한다. 밝은 테마의 세부 색은 아직 시안으로 확정하지 않았다.

## 4. 메인 화면 — 확정

배치 순서는 다음과 같다.

```text
공통 헤더
소개: 왼쪽 사진 / 오른쪽 설명과 경력·관심 분야
Recent blog posts: 큰 카드 1개 / 오른쪽 작은 카드 2개
News Research: 가로형 카드 최대 3개를 세로 배치
공통 푸터
```

### 소개 영역

- 확정 시안처럼 세로 높이가 짧은 두 열 구성이다.
- `백엔드에서 데이터까지, 배우고 만드는 기록.` 제목은 초기 시안보다 작게 유지한다.
- 사진, 소개 문구, 경력·관심 분야 항목은 별도 데이터 파일에서 관리한다.
- 이름·사진·경력은 실제 제공된 정보로 교체한다. 이미지에 등장한 책상 사진은 임시 자리 표시다.
- `소개 더 보기`는 About으로 이동한다.
- 구현 기본안: 데스크톱에서 사진 높이 약 230~280px, 제목 약 28~40px 범위로 화면 폭에 반응하게 한다.

### Recent blog posts

- 공개된 개인 공부·프로젝트 기록 중 발행일이 최신인 3개를 표시한다.
- 첫 번째 글은 왼쪽 큰 카드, 두 번째와 세 번째 글은 오른쪽의 작은 가로형 카드다.
- 카드에는 썸네일, 분류 경로, 날짜, 제목, 요약, 태그를 표시한다. 작은 카드는 공간에 맞춰 요약을 줄일 수 있다.
- 수정일을 갱신해도 발행일 기준 정렬은 바뀌지 않는다.
- 구현 기본안: 동일 발행일이면 고정된 slug 순서로 정렬한다. 글이 3개보다 적으면 존재하는 글만 표시한다.
- 클릭하면 해당 글의 Posts 본문 화면으로 이동한다.

### News Research

- 경제·IT 뉴스로 만든 글이 올라올 자리다. 최신순 최대 3개를 세로로 표시한다.
- 각 행은 왼쪽 사진, 오른쪽 날짜·제목·설명·태그의 가로형 카드다.
- 개인 공부 기록의 Recent blog posts와 별도의 데이터 집합을 사용한다.
- 구현 기본안: 실제 뉴스가 없으면 `뉴스 리서치를 준비 중입니다` 상태를 표시한다. 시안의 예시 제목을 실제 최신 뉴스로 게시하지 않는다.
- 자동 수집·요약·발행은 후속 작업이다. 이번 UI 구현에서 외부 뉴스를 자동 게시하는 작업을 만들지 않는다.
- 뉴스 카드의 연결 대상은 아직 확정하지 않았다. 실제 뉴스 본문을 블로그에 저장할 때 상세 주소를 정하고, 그 전에는 원문 주소가 있는 항목을 원문으로 연결하는 안을 제안한다.

메인에는 큰 THE BLOG 문구, 분야 선택 박스, All blog posts 목록을 추가하지 않는다.

## 5. Posts 화면 — 확정

```text
공통 헤더
태그 필터: 전체 / AI / Python / Study / …
┌─────────────────────┬────────────────────────┐
│ 폴더와 글 미리보기   │ 선택한 글의 본문       │
│                     │                        │
│ DE MAP              │ 제목·날짜·태그·이미지  │
│ BE MAP              │ Markdown 본문          │
│ PROJECT             │                        │
└─────────────────────┴────────────────────────┘
공통 푸터
```

- 본문은 두 열이다. 글 미리보기를 위한 별도 세 번째 열을 만들지 않는다.
- 최초 진입 시 `categories.ts`에 등록한 최상위 항목 중 첫 번째(현재 `DE MAP`)만 펼친다. 하위 폴더와 다른 최상위 항목은 접힌 상태로 둔다.
- 오른쪽은 글을 선택했을 때 본문을 표시한다. 시안은 첫 글을 선택한 상태이며 최초 진입 상태가 아니다.
- 실제 폴더를 펼치면 그 아래에 하위 폴더와 **그 폴더에 직접 들어 있는 글**이 나타난다.
- 하위 폴더의 글은 해당 하위 폴더를 펼쳤을 때 그 안에 나타난다.
- 글 카드는 사진 → 제목·간단한 소개 → 태그 순으로 배치한다.
- 다른 최상위 카테고리를 누르면 기존 최상위 카테고리의 펼쳐진 내용 전체를 접는다.
- 글 카드를 누르면 오른쪽에는 해당 Markdown의 렌더링 결과가 표시된다.

### 폴더 깊이와 카드 위치 — 사용자 확인 사항

```text
DE MAP
  └─ Python
       ├─ [Python에 직접 작성한 글 카드]
       └─ 파이썬 기본기
            ├─ [실행 환경과 패키지 관리 카드]
            ├─ [기본 자료형과 문자열 카드]
            └─ [자료구조 카드]
```

카드는 **소속 폴더의 하위 콘텐츠 영역**에 배치한다. 모든 카드를 왼쪽의 하나의 공통 시작선에 모으지 않는다.

- Python 직속 글과 파이썬 기본기의 글은 들여쓰기 깊이가 다르다.
- 같은 폴더의 카드들은 시작 위치와 너비가 같다.
- 같은 글을 부모 폴더와 자식 폴더의 카드 목록에 중복 표시하지 않는다.
- 글이 있는 부모 폴더와 그 하위 폴더가 동시에 존재할 수 있다.
- 자식 폴더를 펼쳐도 부모 직속 글의 소속과 들여쓰기는 바뀌지 않는다.

구현 기본안: 한 단계의 들여쓰기는 12px부터 조정한다. 폴더의 자식 컨테이너에 한 번 적용하고, 카드에 다시 깊이 전체를 적용하여 들여쓰기가 중복되지 않게 한다. 깊은 폴더에서 카드가 지나치게 좁아지면 데스크톱 왼쪽 패널 내부에 가로 스크롤을 허용하고 카드 최소 너비를 유지한다. 현재 폴더 깊이에서 이 문제가 생기지 않도록 먼저 검증한다.

## 6. Posts 상태와 전환 — 구현 기본안

기존 문서에는 각 클릭 후 화면 상태가 충분히 명시되어 있지 않았다. 다음 규칙으로 구현하면 같은 UI를 일관되게 유지할 수 있다.

| 방문자 동작 | 왼쪽 변화 | 오른쪽 변화 |
|---|---|---|
| 헤더의 Posts로 처음 진입 | 첫 번째 최상위 항목만 펼침 | `왼쪽에서 읽을 글을 선택하세요` |
| DE MAP 열기 | DE 직속 글과 하위 폴더 표시 | 선택 안내 |
| DE 안의 Python 열기 | Python 직속 글과 하위 폴더 표시 | 선택 안내 |
| 하위 폴더 열기 | 해당 분기 펼침, 같은 부모의 다른 열린 분기는 접힘 | 기존 선택 해제 후 안내 |
| 글 카드 클릭 | 카드 선택 표시, 조상 폴더 유지 | 선택한 글 본문 표시 |
| BE MAP으로 전환 | DE의 모든 하위 내용 접힘, BE 내용 표시 | 기존 글 해제 후 안내 |
| 열린 폴더 다시 클릭 | 그 폴더의 내용 접힘 | 그 안의 글을 읽고 있었다면 안내 |
| 태그 변경 | 펼침 경로를 유지하면서 카드 필터링 | 선택 글이 결과에 남으면 유지, 아니면 안내 |
| 메인 카드나 글 주소로 진입 | 해당 글의 조상 폴더를 자동으로 펼침 | 해당 글 표시 |
| 뒤로/앞으로 이동 | 주소에 해당하는 폴더·태그·선택 복원 | 해당 본문 또는 안내 |

상태는 `열린 폴더 경로`, `선택 태그`, `선택 글`로 나누어 관리한다. 글을 담고 있는 폴더가 접혔는데 보이지 않는 카드가 선택 상태로 남지 않게 한다.

### 태그 필터

- 태그 UI의 위치와 AI·Python·Study 같은 형태는 확정 사항이다.
- 구현 기본안은 **한 번에 하나의 태그 선택**이다. `전체`는 태그 제한을 해제한다.
- 선택 태그는 현재 카테고리 안의 글 미리보기에 적용된다. 다른 카테고리를 열어도 태그 선택은 유지한다.
- 세 최상위 항목과 폴더 구조는 유지한다. 공개 글은 있지만 태그에 맞는 글이 없으면 해당 콘텐츠 영역에 결과 없음 안내를 표시한다.
- 태그 목록은 공개된 개인 글의 `tags`에서 생성한다. 이미지의 AI·Python·Study를 내용과 무관하게 강제로 넣지 않는다.
- 같은 태그를 `ML`, `ml`, `#ML`로 써도 하나로 모이도록 공백·앞의 #·대소문자를 정규화한다. 화면에는 대표 표기를 사용한다.
- C++, C#처럼 의미 있는 기호는 보존하고 URL에서는 인코딩한다.
- 최초 진입 때 태그를 먼저 골라도 카테고리를 자동으로 열지 않는다.
- 메인 글 카드의 태그를 누르면 Posts로 이동하고 해당 글의 소속 폴더와 태그가 선택된 목록을 보여준다. 글 제목 링크와 태그 링크를 중첩하지 않는다.

### 빈 상태

- BE MAP과 PROJECT에 공개 글이 없어도 최상위 항목은 표시한다.
- 구현 기본안: 공개 글이 전혀 없는 하위 폴더는 표시하지 않는다. 빈 폴더의 표시가 필요하면 별도 목록 데이터로 관리한다.
- 최상위 빈 분류를 열면 `아직 공개된 글이 없습니다`를 표시한다.
- 이미지 없는 글은 기본 커버를 사용한다. 태그 없는 글은 태그 줄을 생략한다.
- 모든 실제 폴더 단계가 같은 규칙을 따른다. 예를 들어 `SAM_AXI/2026-09`의 월 폴더도 Posts 트리의 하위 폴더로 표현한다.

## 7. 글 파일과 데이터 — 구현 기본안

익숙한 원본 폴더 이름을 유지하면서 공개용 글을 Git 저장소 안에 둔다.

```text
src/content/
├── blog/
│   ├── DE Map/
│   │   ├── Python/
│   │   │   ├── python-overview.md          # 부모 폴더 직속 글 예시
│   │   │   └── 파이썬 기본기/
│   │   │       ├── 01_실행환경_패키지관리.md
│   │   │       ├── 02_문법복습_기본자료형.md
│   │   │       └── 03_자료구조.md
│   │   ├── 기록/
│   │   ├── SAM_AXI/2026-09/
│   │   └── 딥 러닝을 이용한 자연어 처리 입문/
│   ├── BE Map/
│   └── Project Map/
└── news/                                 # 향후 뉴스 데이터
```

`python-overview.md`는 부모 직속 글의 배치를 설명하기 위한 예시이며 현재 원본에 존재하는 글은 아니다. 빈 디렉터리는 Git에 저장되지 않으므로 세 최상위 분야는 별도 설정으로 항상 정의한다.

| 저장 폴더 | 화면 표시 |
|---|---|
| DE Map | DE MAP |
| BE Map | BE MAP |
| Project Map | PROJECT |

### 개인 글 프런트매터

```yaml
---
title: "실행 환경과 패키지 관리"
description: "가상환경과 패키지 관리의 기본을 정리합니다."
pubDate: 2026-09-29
slug: python-environment
tags: [Python, Study]
draft: true
---
```

| 필드 | 규칙 |
|---|---|
| title, description, pubDate | 필수. 화면 제목·요약·실제 발행일 |
| slug | 새 글에서 필수로 지정하는 고유 주소. 발행 후 유지 |
| tags | 선택. 기본 빈 배열 |
| draft | 선택. 기본 false를 제안. 새 글 템플릿은 true로 시작 |
| heroImage | 선택. 로컬 이미지 경로, 없으면 기본 커버 |
| updatedDate | 선택. 수정일 |
| order | 선택. 폴더 안에서 학습 순서를 명시할 때 사용 |

- 카테고리는 파일 경로에서 계산한다. 글마다 `category`를 중복 입력하지 않는다.
- 파일 이름과 폴더명은 한글·공백을 허용하고 비교할 때 Unicode NFC로 정규화한다.
- 글 주소용 slug와 폴더 경로를 분리한다. slug를 유지하면 파일을 다른 폴더로 옮겨도 글 주소는 유지된다.
- 새 slug는 소문자 영문·숫자·하이픈의 한 구간으로 작성하고 컬렉션 안에서 유일해야 한다. 기존 주소는 별도 대응표로 보존한다. 중복 slug는 파일 경로와 함께 빌드 오류로 알린다.
- `01_`, `02_`처럼 번호를 붙인 같은 폴더의 글은 번호순으로 읽도록 한다. 일반 글은 발행일 역순을 기본으로 한다. `order`를 사용한다면 그 폴더의 모든 글에 지정하는 규칙으로 일관성을 유지한다.
- 폴더와 직속 글이 함께 있을 때는 직속 글 목록을 먼저, 하위 폴더 목록을 다음에 배치하는 안을 기본으로 한다. 어느 위치에서도 소속 들여쓰기는 동일하다.
- 공개 조회 함수를 하나로 만들어 초안을 메인·Posts·태그·글 경로·RSS·사이트맵에서 함께 제외한다.
- 초안도 컬렉션에 넣는 이상 필수 필드는 유효해야 한다. 공개할 글은 본문도 있어야 한다.
- 원본 11개를 그대로 로더에 연결하지 않는다. 사용자가 작성한 메타데이터를 검증하고 본문이 있는 글을 초안 상태로 옮긴 뒤, 공개할 글을 선택한다. 실제 발행일을 파일 수정 시각으로 추정하지 않는다.

### 콘텐츠 준비 상태 — 2026-09-29

- 사용자가 `copy_folder`의 글 11개에 제목·요약·발행일·slug·태그·초안 여부를 작성했다. 날짜 필드명은 `pubDate`로 올바르게 입력되어 있다.
- 임시 공통 대표 사진을 생성하여 글 11개의 `heroImage`에 상대 경로로 연결했다. 원본 사진은 `copy_folder/_assets/default-post-cover.png`, 프로젝트용 복사본은 [src/assets/default-post-cover.png](../src/assets/default-post-cover.png)에 있다. [생성 프롬프트](design/default-post-cover-prompt.txt)도 보관한다.
- 이후 콘텐츠를 `src/content/blog`로 옮길 때 `_assets`도 같은 상대 구조로 복사하거나, 프로젝트용 사진을 참조하도록 각 `heroImage` 경로를 조정한다. `_assets`는 카테고리로 표시하지 않는다.
- 같은 사진을 News Research의 임시 기본 커버로 사용할 수 있다. 아직 뉴스 컬렉션이나 뉴스 화면에 연결한 상태는 아니다.
- 글 11개는 현재 모두 `draft: true`다. 공개 여부는 변경하지 않았다. 본문이 없는 글은 실제 포스트 목록에 연결하기 전에 확인한다.
- `기록/AI_관련_요점정리.md`와 `기록/python_기본기.md`의 slug가 모두 `ai-memo`다. 이전 시 고유 주소가 되도록 정리해야 하며, 이번 사진 준비 작업에서는 사용자 입력을 유지했다.
- 사진 연결은 원본 글 폴더에서 완료했으며, 사이트의 실제 화면·라우트 구현과 콘텐츠 이전은 후속 작업이다.

### 뉴스 데이터

`news` 컬렉션을 별도로 두는 안을 제안한다. 개인 글의 세 카테고리 및 Recent blog posts 집계에 섞지 않는다. 뉴스에는 제목·요약·발행 시각·이미지·태그 외에 `sourceName`, `sourceUrl`을 둘 수 있다. 수집·중복 방지·요약·자동 발행은 별도 설계에서 다룬다.

## 8. Astro 코드 구조 — 구현 기본안

현재의 정적 배포 방식을 유지한다. 콘텐츠는 빌드할 때 읽고, 브라우저에서는 폴더 펼침·태그 선택·테마 전환만 처리한다. 현 단계에서 React 같은 UI 프레임워크를 추가할 필요는 없다.

```text
src/
├── content.config.ts
├── data/
│   ├── site.ts                     # 이름·메뉴·소개·링크
│   └── categories.ts               # 세 최상위 폴더와 표시 이름
├── lib/
│   ├── posts.ts                    # 공개 글 조회와 정렬
│   ├── post-tree.ts                # 폴더별 직속 글과 자식 폴더
│   ├── tags.ts                     # 태그 정규화와 필터
│   └── post-urls.ts                # URL 생성과 상태 해석
├── components/
│   ├── Header.astro / Footer.astro / BaseHead.astro
│   ├── ProfileHero.astro
│   ├── PostCard.astro              # 메인·좌측 카드의 공통 데이터
│   ├── NewsCard.astro
│   ├── TagFilter.astro
│   ├── CategoryNode.astro          # 폴더를 재귀적으로 표시
│   └── PostReader.astro
├── layouts/
│   ├── SiteLayout.astro           # 공통 헤더·푸터·폭
│   └── PostsLayout.astro          # 태그·왼쪽 트리·오른쪽 본문
├── scripts/
│   └── posts-browser.ts           # 펼침·필터·브라우저 상태
├── styles/
│   ├── global.css
│   └── prose.css                  # Markdown 제목·표·코드
└── pages/
    ├── index.astro
    ├── posts/index.astro
    ├── posts/[...slug].astro
    ├── about.astro
    └── rss.xml.js
```

핵심 트리 데이터는 다음 두 목록을 구분해야 한다.

```ts
type FolderNode = {
  id: string;            // 전체 경로 기반 식별자
  name: string;          // 화면의 폴더 이름
  depth: number;
  directPostIds: string[];
  children: FolderNode[];
};
```

`directPostIds`에 모든 하위 폴더의 글까지 넣으면 카드 중복과 잘못된 들여쓰기가 생긴다. 부모별 직속 글과 자식 폴더를 나누어 재귀 렌더링한다. 폴더 식별자는 이름 하나가 아닌 전체 경로를 사용하여 서로 다른 위치의 같은 이름을 구별한다.

로컬 콘텐츠의 `filePath`로 폴더를 구하고, 고정 slug는 글 주소에만 사용한다. 전체 글 본문을 브라우저 데이터에 한꺼번에 싣지 않는다. 트리에는 제목·요약·이미지·태그·주소 등 미리보기 정보만 포함하고, 오른쪽 본문은 선택한 글의 정적 HTML에 포함한다.

### 주소와 새로고침

| 주소 | 역할 |
|---|---|
| `/` | 메인 |
| `/posts/` | 첫 번째 최상위 카테고리를 펼친 목록과 글 선택 안내 |
| `/posts/python-environment/` | 같은 Posts 레이아웃 안에서 글 표시 |
| `/posts/?folder=…&tag=python` | 선택 폴더와 태그에 해당하는 목록 상태 |
| `/about/` | 소개 |

- 글별 HTML은 `getStaticPaths()`로 생성하고, 글 링크는 실제 `<a href>`를 사용한다.
- 선택 글이 있으면 그 파일 경로가 조상 폴더 펼침 상태의 기준이다.
- 폴더와 태그 상태는 `URLSearchParams`로 읽고 쓴다. 사용자가 클릭한 전환은 history에 기록하고 `popstate`에서 복원한다.
- 목록에 폴더 지정 없이 처음 진입하면 첫 번째 최상위 폴더를 열고 `replaceState`로 주소에 반영한다. 이후 사용자가 모두 접은 상태와 뒤로/앞으로 이동도 유지한다. 특정 폴더나 글 주소로 진입하면 해당 경로를 우선한다.
- 정적 호스팅에서는 쿼리를 빌드 시점의 분기 조건으로 사용하지 않는다. 쿼리 기반 접힘·필터 상태는 브라우저에서 복원한다.
- 접힌 목록을 직접 열면 오른쪽에 빈 상태를 표시한다. 글 주소를 직접 열면 본문이 HTML에 존재해야 한다.
- 태그 변경으로 선택 글이 제외되면 선택 글 주소를 목록 주소로 바꾸고 본문을 숨긴다. 주소와 표시 내용이 어긋나지 않게 한다.
- 글 주소에 맞지 않는 태그 쿼리가 붙어 들어오면 해당 글을 보여주고 태그를 전체로 정리하는 안을 기본으로 한다.
- 단순 문서 이동으로 먼저 동작을 완성한다. 이후 부드러운 화면 전환을 추가해도 링크·새로고침·뒤로 가기 동작을 유지한다.
- JavaScript가 꺼져도 글 주소의 본문과 기본 탐색 링크는 읽을 수 있도록 점진적으로 기능을 추가한다.
- 기존 `/blog/`와 `/blog/<id>/`의 연결을 새 주소로 옮길 때 대응표를 작성하고 이전 주소를 유지하는 정적 리다이렉트 파일을 만든다. 사이트맵과 canonical은 새 주소를 가리킨다.
- 필터 쿼리는 별도 본문 페이지로 취급하지 않고 canonical에서 제거한다.

현재 소스의 RSS 링크·HeaderLink 활성 표시·BaseHead 공유 이미지도 새 경로와 메타데이터에 맞춰 함께 바꿔야 한다.

## 9. 모바일과 긴 콘텐츠 — 구현 기본안

- 데스크톱은 왼쪽 약 30%, 오른쪽 약 70%로 시작하며 왼쪽 최소 너비와 본문 읽기 폭을 확보한다.
- 데스크톱 Posts에서는 헤더와 태그 영역 아래의 좌측 목록과 우측 본문을 각각 세로 스크롤할 수 있게 한다. 글 선택 시 우측 읽기 위치는 맨 위로, 좌측 목록의 스크롤 위치는 유지하는 안을 기본으로 한다.
- 약 960px 미만에서는 한 열을 사용한다. 목록 선택 후 본문을 보여주고 `글 목록으로`로 폴더·태그 상태를 복원한다.
- 태그는 한 줄 가로 스크롤로 유지한다.
- 좁은 화면에서는 소개 사진과 소개 문구를 위아래로 배치한다.
- 긴 폴더명과 제목은 줄바꿈하고, 표·코드 블록은 해당 영역 안에서 가로 스크롤한다.
- 본문 이미지에는 최대 폭을 적용한다. 페이지 전체에 가로 스크롤이 생기지 않게 한다.
- 첫 화면 밖의 카드 이미지는 지연 로딩한다. 이미지 비율과 크기를 미리 확보해 목록 위치가 갑자기 밀리지 않게 한다.
- 선택한 폴더 버튼과 글 카드에는 현재 상태를 전달하는 접근성 속성을 적용한다. 폴더 펼침은 버튼, 글 이동은 링크를 사용한다.
- 글 이동 후 본문 제목에 포커스를 옮기는 등 키보드 사용자가 변경된 내용을 찾을 수 있게 한다.

## 10. 구현 순서

1. 공통 차콜 스타일, 동일한 컨테이너, 헤더·푸터를 만든다.
2. 공개 조회·메타데이터·폴더 트리를 만들고 부모 직속 글과 하위 글이 구분되는지 확인한다.
3. Posts의 최초 상태, 펼침, 카드 선택, 본문을 구현한다.
4. 태그와 URL·뒤로 가기 상태를 연결한다.
5. 같은 글 데이터를 메인의 Recent blog posts에 연결한다.
6. News Research의 카드 레이아웃과 데이터 없는 상태를 만든다.
7. 모바일, 키보드 조작, 기존 URL, RSS·메타데이터를 확인한다.
8. 시안과 실제 브라우저 화면을 비교하고 간격·폰트·줄바꿈을 조정한다.

실제 뉴스 자동 발행 작업은 이 순서와 분리하여 후속으로 진행한다.

## 11. 구현 완료 확인 기준

### 화면

- [ ] 메인 헤더 구분선과 Recent blog posts의 좌우 끝이 일치한다.
- [ ] 소개 영역 높이와 제목 크기가 최종 메인 시안에 맞는다.
- [ ] 최근 개인 글 3개와 뉴스 최대 3개가 각각 지정된 배치와 최신순으로 보인다.
- [ ] 글 카드에 대각선 화살표가 없고, 메인에 분야 박스·All blog posts가 없다.
- [ ] Posts 헤더 아래에 태그, 본문에는 왼쪽 탐색과 오른쪽 본문의 두 열만 있다.

### 폴더와 글

- [ ] `/posts/`에 처음 들어오면 세 최상위 항목만 보인다.
- [ ] Python 직속 테스트 글과 파이썬 기본기 글을 동시에 넣어 서로 다른 깊이에 표시되는지 확인한다.
- [ ] 부모의 카드 목록에 자식 폴더 글이 중복되지 않는다.
- [ ] 같은 소속의 카드들은 들여쓰기와 폭이 같다.
- [ ] 다른 최상위 분류를 열면 이전 분류의 하위 폴더와 글 카드가 전부 접힌다.
- [ ] 같은 이름의 폴더가 다른 위치에 있어도 충돌하지 않는다.
- [ ] 빈 최상위 카테고리, 이미지 없는 글, 태그 없는 글에 정상적인 상태를 표시한다.

### 상태·발행·호환성

- [ ] 태그와 폴더 조건이 함께 적용되고 결과가 없을 때 안내가 나온다.
- [ ] 선택 글이 필터에서 제외되면 URL과 본문 선택이 함께 정리된다.
- [ ] 메인 카드 클릭, 주소 직접 접속, 새로고침, 뒤로/앞으로 가기에서 같은 글과 폴더가 복원된다.
- [ ] 초안이 직접 글 주소·RSS·사이트맵을 포함해 공개 결과물에 나타나지 않는다.
- [ ] slug를 유지하면서 폴더를 옮겨도 글 주소는 바뀌지 않는다.
- [ ] 예전 글 주소가 대응하는 새 주소로 연결된다.
- [ ] 작은 화면에서도 태그·폴더·글 선택과 본문 읽기가 가능하다.
- [ ] 빌드와 실제 브라우저 확인을 통과한다. 검증용 글은 최종 공개 목록에 남기지 않는다.

## 12. 아직 시안으로 확정하지 않은 내용

구현 기본안으로 진행할 수 있는 부분: 태그 단일 선택, 같은 부모의 폴더 하나씩 펼치기, 정렬의 세부 기준, 모바일 전환, 밝은 테마, URL 형식.

실제 콘텐츠를 연결할 때 필요한 부분: 본인 사진·소개·경력·연락 링크, 원본 학습 글의 제목·발행일·공개 여부, 현재 기본 템플릿 글의 유지 여부, 뉴스의 실제 데이터와 연결 대상, About 본문.

이 항목들은 이번 이미지에 있는 예시만으로 실제 정보가 확정되었다고 취급하지 않는다. 화면과 탐색 로직은 콘텐츠 자리 표시를 사용하여 먼저 구현할 수 있다.

## 13. 이번 문서 검토에서 보완한 점

| 기존 메모의 부족한 점 | 보완한 기준 |
|---|---|
| 소스 저장소 밖에 문서와 시안이 있음 | 저장소 `docs` 안에 기준 문서와 두 이미지를 함께 보관 |
| 사용자 확정과 기술 제안이 섞임 | 확정 UI와 구현 기본안을 구분 |
| 폴더의 글이 직속인지 전체 하위인지 불명확 | 직속 글만 저장하고 자식 폴더를 별도 순회 |
| 깊이에 따른 카드 위치가 명시되지 않음 | 폴더 하위 콘텐츠에 들여쓰기, 부모·자식 중복 금지 |
| 클릭 후 본문과 필터의 상태가 부족함 | 상태 전환 표, 빈 상태, URL 복원 규칙 추가 |
| 메인과 Posts의 글 연결이 빠짐 | 같은 데이터와 고정된 글 주소를 사용 |
| 뉴스 자동 발행과 현재 UI 범위가 섞일 수 있음 | News Research 표시와 후속 자동화 범위를 구분 |
| 콘텐츠 이전·초안·이전 주소·모바일 기준이 없음 | 데이터 규칙, 이전 절차, 검증 기준 추가 |

## 14. 구현 근거

- [Astro 콘텐츠 컬렉션](https://docs.astro.build/en/guides/content-collections/): 로컬 MD·MDX 로딩, 스키마, 공개 글 필터와 본문 렌더링.
- [Astro CollectionEntry](https://docs.astro.build/en/reference/modules/astro-content/#collectionentryfilepath): 로컬 파일 경로와 글 ID의 구분.
- [Astro 라우팅](https://docs.astro.build/en/guides/routing/): 정적 글 경로 생성과 경로 대응.
- [Astro 컴포넌트](https://docs.astro.build/en/basics/astro-components/): 공통 화면 구성.
- [Astro 스타일](https://docs.astro.build/en/guides/styling/): 공통 스타일과 컴포넌트 스타일.

문서의 UI·상태 정책은 사용자 요구와 현재 소스를 바탕으로 한 프로젝트 설계다. 공식 문서가 이 화면 구성을 자동 제공한다는 의미는 아니다.
