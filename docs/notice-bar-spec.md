# 메인 페이지 공지사항 개발 설계

작성일: 2026-10-04

상태: **구현 및 로컬 검증 완료**

적용 위치: 메인 페이지의 소개 영역 아래, `땃땃한 최신글` 위

## 1. 최종 화면

```text
프로필 사진 / 블로그 소개

공지   [· 블로그 이용 안내]   [글 안에서 Python을 실행해 보세요]   [학습 기록 업데이트 안내]

땃땃한 최신글
최근 글 카드
```

그림의 대괄호는 제목 박스를 뜻합니다. 실제 화면에 대괄호 문자를 출력하지 않습니다.
제목은 예시이며, 실제로는 글의 `title`을 사용합니다.

### 확정한 디자인

- 왼쪽에 **`공지` 글자만** 표시합니다. 확성기와 다른 장식 아이콘을 추가하지 않습니다.
- 공지 영역 위아래에 구분선을 넣지 않습니다. 영역 전체 배경은 메인 배경과 이어집니다.
- 제목 박스 안을 중립적인 짙은 회색으로 채우고, 평상시 외곽선은 표시하지 않습니다.
- 모서리는 직각에서 살짝만 둥글립니다.
- 글씨와 박스 높이는 작게, 박스 좌우 여백은 글씨에 가깝게 잡습니다.
- 제목 박스는 글자 길이에 맞는 너비를 사용합니다. 세 칸을 같은 너비로 늘리지 않습니다.
- 가장 최근 공지의 제목 앞에는 작은 점을 표시합니다. 점은 제목 박스 안에만 들어갑니다.
- 서로 다른 공지 글은 최대 3개, 한 줄로 표시합니다.
- 제목이 전부 들어오면 정지하고, 넘칠 때만 천천히 왼쪽으로 순환합니다.

직전 이미지의 확성기 아이콘은 이번 문서에서 제외했습니다. 개발 시 위 기준을 적용합니다.

### 구현할 때 시작할 크기와 색상

아래 수치는 초기값입니다. 실제 브라우저에서 기존 화면과 비교해 소폭 조정합니다.

| 항목 | 초기값 |
| --- | --- |
| `공지` 글씨 | 13px, 중간 굵기, 기존 `--muted` 색상 |
| 제목 글씨 | 13px, 일반 굵기, 한 줄 |
| 제목 박스의 보이는 높이 | 약 28px |
| 좌우 내부 여백 | 각 8~10px |
| 모서리 | 4px |
| 박스 사이 간격 | 8px |
| 라벨과 제목 목록 사이 간격 | 14px |
| 어두운 테마 | 박스 `#2b2b2b`, 글씨 `#dedede` |
| 밝은 테마 | 박스 `#e9e9e5`, 글씨 `#303030` |
| 최신 공지의 점 | 4px, 중립적인 회색 |
| 소개와 공지 사이 / 공지와 최신글 사이 | 각각 약 24px |

링크의 투명한 위아래 여백을 포함해 누를 수 있는 높이는 44px을 확보합니다.
따라서 보이는 제목 박스는 낮게 유지하면서 손가락으로 누를 수 있습니다.
포인터를 올리면 배경을 약간 밝게 바꾸고, 키보드 초점에는 눈에 보이는 윤곽선을 표시합니다.

## 2. 현재 코드에서 재사용할 부분

| 현재 파일 | 확인한 역할 | 이번 기능에서 사용하는 방법 |
| --- | --- | --- |
| `src/pages/index.astro` | 소개 → 최근 글 → 뉴스 순서로 출력 | 소개와 최근 글 사이에 공지 컴포넌트 삽입 |
| `src/lib/posts.ts` | 공개 글만 골라 발행일 최신순으로 반환 | 같은 글 목록에서 공지와 최근 글을 각각 선택 |
| `src/lib/tags.ts` | 태그의 앞뒤 공백·앞쪽 `#`·유니코드 표현을 정리 | `matchesTag(tags, '공지사항')` 사용 |
| `src/lib/post-tree.ts` | 발행일과 slug를 기준으로 정렬 | 같은 정렬 규칙 재사용 |
| `src/lib/post-urls.ts` | 글 주소를 생성 | `postsUrl('', '', post.slug)` 사용 |
| `src/content.config.ts` | `title`, `pubDate`, `tags`, `draft` 등 검증 | 기존 필드를 그대로 사용 |

메인에서는 `getPosts()`를 한 번 호출해 전체 공개 글을 받아 둡니다.
공지 선택은 이 전체 목록에서 합니다. 최근 글 3개를 먼저 자른 목록에서 공지를 찾으면 오래된 공지를 놓칠 수 있습니다.

현재 `.profile-hero`에는 아래 여백이 데스크톱 52px, 모바일 38px로 설정되어 있습니다.
공지 유무를 나타내는 메인 클래스에 따라 이 여백을 조정해, 공지를 추가했을 때 여백이 중복되지 않게 합니다.

## 3. 어떤 글을 공지로 선택할지

1. 기존 `blog` 컬렉션의 공개 글을 가져옵니다.
2. `tags`에 **`공지사항`**이 있는 글을 찾습니다.
3. `pubDate` 최신순으로 정렬합니다. 날짜가 같으면 기존 규칙대로 slug로 순서를 고정합니다.
4. 앞에서 최대 3개를 선택합니다.
5. 각 글의 `title`과 기존 글 주소를 화면에 전달합니다.

### 세부 규칙

- `공지사항`, `#공지사항`, 앞뒤 공백이 있는 `공지사항`은 기존 태그 처리 규칙으로 같은 태그로 봅니다.
- `공지`, `알림`은 자동으로 같은 태그로 취급하지 않습니다. 작성할 때는 `공지사항`으로 통일합니다.
- `draft: true`인 글은 공지에도 나오지 않습니다.
- 카테고리에 관계없이 찾습니다. `Blog` 폴더에 작성하는 것을 권장하지만 필수는 아닙니다.
- `updatedDate`를 바꿔도 공지 순서는 바뀌지 않습니다. 정렬 기준은 발행일입니다.
- 한 글에 같은 태그가 여러 번 있어도 공지는 한 번만 선택됩니다.
- 공지 후보가 4개 이상이면 나머지 글은 Posts에서 계속 볼 수 있습니다.
- 공지 태그를 제거하면 다음 빌드부터 공지 영역에서 빠집니다.
- 공지로 선택된 글도 최근 글·Posts·RSS의 기존 선택 규칙을 그대로 따릅니다.

**구현 기본안:** 공지는 일반 글에 태그로 표시합니다. 별도 공지 컬렉션, 고정 순서, 만료일 필드는 이번에 추가하지 않습니다.
현재 블로그의 `draft` 공개 정책을 따르며, 미래 날짜를 입력한다고 자동 예약 발행되지는 않습니다.

## 4. 글 작성 방법

예를 들어 `src/content/blog/Blog/공지사항/블로그_이용_안내.md`에 다음처럼 작성합니다.

```md
---
title: "블로그 이용 안내"
description: "글 탐색과 Python 실습 기능을 소개합니다."
pubDate: 2026-10-04
slug: blog-guide
tags: [Blog, 공지사항]
draft: true
---

## 블로그 이용 안내

여기부터 공지 본문을 작성합니다.
```

공개할 때 `draft: false`로 바꾸고 평소처럼 빌드·배포합니다.
MDX 글에도 같은 메타데이터를 사용합니다.
메인의 요약 영역에는 `description` 대신 **`title` 한 줄**이 표시되고, 누르면 해당 글 본문으로 이동합니다.
정적 사이트이므로 새 글과 태그 변경은 배포가 완료된 뒤 반영됩니다.

## 5. 공지 개수와 제목 길이에 따른 동작

| 상황 | 화면과 동작 |
| --- | --- |
| 공개 공지가 0개 | 라벨·영역을 함께 숨기고 기존 소개 아래 여백 사용 |
| 1~3개, 모든 제목이 들어옴 | 라벨과 제목을 정지 상태로 표시 |
| 1~3개, 제목 합계 너비가 넘침 | 라벨을 고정하고 제목 목록만 왼쪽으로 천천히 이동 |
| 제목 한 개가 화면보다 길음 | 줄바꿈 없이 전체 제목이 순환하며 읽히도록 처리 |
| 제목 클릭 | 해당 글의 `/posts/<slug>/`로 이동 |
| 창 크기 또는 글꼴 크기 변경 | 제목 너비를 다시 측정해 정지/이동 상태 결정 |

제목은 저장된 문자열을 그대로 출력합니다. 임의로 요약하거나 잘라 저장하지 않습니다.
기본 제목 박스에 `text-overflow: ellipsis`를 적용하지 않고, 넘치는 내용은 공지 목록 영역 안에서만 잘립니다.
페이지 전체에 가로 스크롤이 생기지 않도록 합니다.

## 6. 자동 이동과 읽기 편의

### 기본 이동

- 방향: 오른쪽에서 왼쪽.
- 초기 속도: 초당 약 18px. 제목이 길어져도 이동 속도는 일정하게 유지합니다.
- 처음에는 약 1.5초간 정지한 뒤 이동합니다.
- `공지` 라벨은 항상 같은 위치에 있습니다.
- 끝까지 이동한 제목 묶음이 오른쪽에서 자연스럽게 이어지도록 같은 묶음을 반복 배치합니다.
- 원본 목록의 너비와 묶음 사이 간격을 더한 만큼 이동하면 한 주기가 끝납니다.
- 반복용 복사본은 표시를 위한 것이며, 공지 선택 데이터는 최대 3개로 유지합니다.

### 멈추기와 모바일

- 포인터를 공지 영역에 올리면 현재 위치에서 잠시 멈춥니다.
- 자동 이동이 필요한 경우에만 오른쪽에 작은 **`멈춤` / `재생` 텍스트 버튼**을 제공합니다.
- 버튼으로 멈추면 사용자가 재생을 선택할 때까지 자동으로 다시 움직이지 않습니다.
- 키보드로 제목에 초점을 옮기면 자동 이동을 중단하고, 선택한 원본 링크를 화면 안에 보여 줍니다.
- 모바일에서 목록을 터치하면 자동 이동을 멈추고 가로 스와이프로 제목을 읽을 수 있게 합니다. 링크 탭도 가능해야 합니다.
- 수동 읽기 상태에서는 제목의 원래 순서로 가로 스크롤할 수 있게 하며, 재생 버튼으로 자동 이동을 다시 시작합니다.
- 시스템의 **모션 줄이기** 설정이 켜져 있으면 자동 이동을 사용하지 않고 수동 가로 스크롤을 제공합니다.
- JavaScript가 꺼져 있거나 초기화에 실패해도 원본 제목과 링크를 읽고 가로 스크롤할 수 있어야 합니다.

`멈춤` 버튼은 정적인 시안에는 없는 **구현 기본안**입니다. 터치 사용자도 움직임을 직접 멈출 수 있도록, 넘칠 때만 나타납니다.

### 접근성 처리

- `공지`를 실제 영역 제목으로 사용하고, 공지 목록과 연결합니다.
- 원본 제목은 일반 `<a>` 링크로 제공해 새 탭 열기와 키보드 이동을 지원합니다.
- 반복 표시용 복사본은 `aria-hidden="true"`로 하고 Tab 이동 대상에서 제외합니다. 포인터로 누르면 같은 글로 이동합니다.
- 화면 읽기 프로그램에는 원본 공지 목록만 한 번 전달합니다. 자동 이동 때문에 제목을 반복 낭독하지 않습니다.
- 키보드 초점이 복제본이나 잘린 화면 밖에 머물지 않도록, 초점 진입 시 원본 목록의 수동 읽기 상태로 전환합니다.
- 최신 공지의 점은 장식으로 숨기고 해당 원본 링크에 `가장 최근 공지`라는 보조 설명을 제공합니다.
- 제목은 HTML 문자열로 삽입하지 않고 Astro의 텍스트 출력으로 처리합니다.

### 데이터가 화면으로 전달되는 순서

```text
MD / MDX 글의 메타데이터
  → getPosts(): 공개 글을 준비
  → getNotices(allPosts): 공지사항 태그 / 최신순 / 최대 3개
```

React 등 별도 화면 프레임워크 없이 Astro 컴포넌트와 브라우저 스크립트로 구현합니다.
공지 데이터 선택은 빌드 시 수행하고, 브라우저에서는 표시 동작만 담당합니다.

## 8. 이동 구현 시 주의할 점

1. **원본 목록의 너비만 측정합니다.** 복제본이 추가된 전체 너비로 검사하면 항상 넘친다고 판단할 수 있습니다.
2. `ResizeObserver`로 표시 영역과 원본 목록의 너비 변화를 감지하고, 글꼴 준비 후에도 다시 측정합니다.
3. 제목 너비가 표시 영역을 1px 이상 넘을 때만 자동 이동 후보로 봅니다.
4. 복제본은 최초 HTML에 넣지 않고, 자동 이동이 필요할 때만 만듭니다. 초기 화면과 JavaScript 비활성 상태에서는 중복이 없습니다.
5. 이동 거리는 `원본 목록 너비 + 묶음 간격`, 시간은 `이동 거리 ÷ 이동 속도`로 계산합니다.
6. 이동에는 `transform`을 사용합니다. 매 프레임 제목의 위치를 JavaScript로 계산하지 않습니다.
7. 제어 버튼의 출현이 너비 측정을 반복해서 흔들지 않도록, 버튼 공간을 포함해 상태를 계산하고 같은 상태에서는 다시 초기화하지 않습니다.
8. 창이 넓어져 제목이 모두 들어오면 애니메이션·복제본·이동 제어 버튼을 정리하고 처음 순서로 보여 줍니다.
9. 모션 설정이 바뀌거나 페이지를 벗어나면 애니메이션·관찰자·이벤트를 정리합니다. 뒤로 돌아온 경우에도 링크와 상태가 정상이어야 합니다.
10. 기존 전역 스타일의 모션 줄이기는 `transition`만 끕니다. 공지 애니메이션은 별도로 정지 처리해야 합니다.

## 9. 구현 순서와 검증 기준

브라우저 검증에는 짧은 제목과 긴 제목의 별도 테스트 데이터를 사용합니다.
검증용 공지 글을 실제 공개 글로 남기지 않습니다.

`tests/fixtures/astro.config.mjs`에서만 테스트 페이지를 등록합니다. `npm run test:e2e`는
이 설정으로 `dist-e2e`에 별도 빌드한 뒤 검사합니다. 일반 `npm run build`의 `dist`와 GitHub 배포에는
테스트 페이지가 포함되지 않습니다.

```sh
npm run check
npm test
npm run build
npm run test:e2e
```

화면 코드에는 공지 선택, 스타일, 움직임을 수정할 위치를 한국어 주석으로 표시했습니다.


### 검증 결과 (2026-10-04)

- `npm run check`: 오류·경고·힌트 0개.
- `npm test`: 11개 통과.
- `npm run test:e2e`: 공지 7개를 포함한 전체 20개 통과.
- `npm run build`: 배포용 35개 페이지 생성 완료. `dist`에 테스트 페이지가 없음을 확인.
