## 가상환경 관리 (venv, virtualenv, conda)

### venv (Python 내장)

Python 프로젝트에서 가상환경은 의존성 충돌을 피하고 프로젝트 별 독립성을 보장하는 핵심도구.

> 의존성 출돌은 피한다고?

파이썬 OS는 전역에 하나만 설치됨. 각 프로젝트마다 독립적인 환경구성이 없다면

프로젝트마다 서로 다른 라이브러리를 요구할 시 발생되는 의존성 문제가 생김

### 가상환경 활성화

`python -m venv 프로젝트명`

### 가상환경 접속

```bash
Windows : `프로젝트명\Scripts\activate`

Mac/Linux : `source 프로젝트명/bin/activate`

패키지 설치 : `pip install pandas requests`
```

### 의존성 버전 기록 및 복원
**데이터 엔지니어링 파이프라인** : 로컬 개발 > 테스트 서버 > 운영 서버

각 라인 당 패키지와 버전을 정확히 기록해서 구성해야됨

```bash
# 기록하기 (로컬) 
pip freeze > requirements.txt
```

이렇게 하면 폴더에 해당 파일이 생김 (Maven 의 pom.xml)

복원하기(운영 서버 또는 새로운 환경)

새 서버에서 코드를 다운받고, 빈 가상환경을 만들고 아래 명령어를 치면 로컬과 똑같은 환경이 구성됨

```bash
# 복원하기
pip install -r requirements.txt
```

나중에 Docker와 Airflow 환경 구성 단계로 갈 때 해당 빌드의 가벼운 방식을 주로 사용
